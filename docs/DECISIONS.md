# 인터페이스 보충 결정 (DECISIONS)

TRD 5절이 모양을 정하지 않은 곳을 M0 인터페이스 자리 단계에서 정한 기록이다. **승인된 DECISIONS 항목이 해당 TRD 조항보다 우선한다. TRD v0.6에서 정리한다.** 바꾸려면 관리자에게 제안한다.

## 0. 공통 규칙

- **모든 mask는 참 = 이 게임(초파리)에 적용.** `reset`, `step`, `on_release`, `on_eaten`, `flush_learning`, `alive` 등 어떤 mask든 참인 칸만 처리하고 거짓인 칸은 건드리지 않는다. 모양 `(B,)`는 게임, `(B,F)`는 초파리 단위다.

## 1. 사건 (core/events.py)

- 초파리 번호 `fly`: `CATCH`, `EATEN`, `Z_CHANGE`, `ALL_RELEASED`는 `fly >= 0`. 그 밖의 종류는 `fly == -1`. 어기면 생성 시 `ValueError`.
- 이유: `fly = -1`이 numpy 인덱스로 들어가면 오류 없이 마지막 초파리를 가리킨다. 체제는 `R[ev.fly]` 대신 `R[fly_index(ev, F)]`(`regimes/base.py`)를 쓴다. 이 함수는 `0 <= fly < F`를 검사한다.
- `cause` 사용법:
  - `GAME_OVER`: 승자. `FLIES`, `PACMAN`, `CENSORED` 중 하나.
  - `Z_CHANGE`: 원인. `POWER_START`, `POWER_END`, `REVIVE` 중 하나.
  - 그 밖의 종류: 반드시 `None`.
- `active`: 사건을 만드는 순간의 학습 활성 여부 (TRD 4.5).

## 2. 냄새 장 (field/odor.py)

- `Field(map, D, lam)`의 시그니처는 TRD 그대로다. 게임 수 `B`는 **첫 `reset(mask)`의 mask 길이**로 정해진다.
- `reset` 전에 `step`, `c`, `total`을 부르면 `RuntimeError`. 이후 mask 길이가 처음 `B`와 다르면 `ValueError`. `S`의 모양이 `(B,N)`이 아니어도 `ValueError`.
- `step(S, mask)`의 mask는 `(B,)` bool이고 **참인 게임만 갱신**한다 (거짓 = 동결).


## 2-1. 감각 (senses/sense.py)

- `sense(odor, phero, views, info, c0, *, nbr)`: TRD 5.4의 표가 이웃표 `nbr`(N,4)의 출처를 정하지 않아, 키워드 전용 인자 `nbr`을 더했다. 위치 인자 다섯 개는 TRD 그대로다. 실행기는 `nbr=map.nbr`를 넘긴다. `legal`, `decide`는 `info`(엔진의 `decision_info()`)를 그대로 쓴다.

## 2-2. 맵 (maps/original.py)

- 미로 원본은 `maps/_maze_data.py`(pacman-ai의 `maze_data.py`에 머리말만 붙여 그대로 복사). 칸 번호는 행 우선 순서 0..319.
- 열은 감싸서 터널을 이웃표에 연결한다 (14행 0열 ↔ 27열).
- `fly_starts`: 0번은 집 밖(원본 Blinky 자리), 1~3번은 집 안.
- `move_mask["pacman"]`은 유령 집·문으로 들어가는 이동을 막고, `move_mask["fly"]`는 `nbr >= 0` 전부.

## 3. 엔진 (engine/game.py)

- `Game`은 한 판 단위, `VecGame(B, map, cfg, rngs)`는 `Game` B개를 도는 얇은 묶음이다. 규칙은 `Game`에만 있다 (TRD 원칙 1).
- `VecGame` 메서드와 반환 모양 (게임 인덱스 `b = 0..B-1`):

| 메서드 | 입력 | 반환 |
|---|---|---|
| `step_pacman(actions)` | `(B,)` 절대 방향 | `list[list[Event]]` (게임별) |
| `step_flies(actions)` | `(B,F)` 자기중심 행동, -1 = 유일한 경로 | `(events: list[list[Event]], moved (B,F) bool, committed (B,F) bool, active (B,F) bool)` (뜻은 4.1절 표) |
| `tick_timers()` | | `list[list[Event]]` |
| `views()` | | `list[GameView]` (길이 B) |
| `decision_info()` | | `(legal (B,F,4) bool, decide (B,F) bool)` |
| `reset_life(mask)` | `(B,)` bool | 없음. mask가 참인 게임만 |
| `reset_game(mask, rngs)` | `(B,)` bool, 칸별 엔진 생성기 `GameRngs` | 없음. mask가 참인 게임 `b`에 `rngs[b]`를 주고 새 판을 시작한다. **관리자 결정 2026-11-08 — TRD 5.2의 수정, TRD v0.6에 반영할 것** |
| `retire(mask)` | `(B,)` bool | 없음. mask가 참인 게임의 `learning_active`만 거짓으로 내린다. 새 판은 시작하지 않고 동결은 유지한다. **TRD 5.2에 없는 메서드다. 총책임자 결정 — TRD v0.6에 반영할 것** |

- 자동 초기화 없음. 초기화는 실행기만 부른다.
- `retire`는 모든 판을 끝낸 칸을 은퇴시킬 때 실행기가 부른다 (7절). 새 판이 시작되지 않는 칸은 `reset_game`을 거치지 않으므로, 학습 활성이 종료 처리 뒤에도 켜진 채 남지 않게 하려는 것이다.
- `Game`의 같은 이름 메서드는 한 판 모양이다 (`step_flies`는 `(F,)` 입력, `decision_info`는 `(F,4)`, `(F,)` 반환, `view()`, `reset_game(rng)`).
- **엔진 난수 계약 (관리자 결정 2026-11-08, `engine/game.py` 모듈 docstring에 같은 글):**
  - 판을 시작할 때마다(**판 1 포함**) 실행기가 `Game.reset_game(rng)`로 그 판의 생성기 `make_rng(시드, 판 번호, "engine")`을 준다. 판 번호는 1부터 (이전에는 판 0번 생성기 하나를 모든 판에 썼다).
  - 엔진은 받은 생성기로 자기 난수를 바꾸고 다음 `reset_game`까지 그것만 쓴다. 다른 생성기나 전역 난수(`np.random.*`, `random.*`)를 쓰지 않는다.
  - `reset_life`는 난수를 바꾸지 않는다 (목숨이 바뀌어도 그 판의 난수열은 이어진다).
  - 생성자의 `rng`는 TRD 5.2 모양 때문에 남은 자리다. 실행기가 실행 시작 때 곧바로 `reset_game(rng)`를 부르므로 엔진은 생성자의 `rng`로 난수를 뽑지 않는다.
  - 생성자 재호출 방식을 고르지 않은 이유: 판마다 엔진 객체를 새로 만들면 엔진 내부의 미리 계산한 표를 다시 만들고 `Game.index`도 다시 붙여야 한다.
  - 시험: `tests/test_engine_rngs.py` (판 시작마다 받은 생성기 = (시드, 판 번호, "engine"), `engine.kind`마다 돌고 진짜 엔진이 생기면 자동으로 돈다. 매 틱 엔진 난수를 뽑는 대역으로 묶음 크기 · 칸 순서와 무관함을 확인).

## 4. 유령 조종기 (brain/base.py)

초파리 뇌, B0, B1, 무작위 초파리가 같은 모양이다. `B` 게임 수, `F` 초파리 수.

| 메서드 | mask / 입력 모양 |
|---|---|
| `propose(obs, alive, views=None)` | `alive` `(B,)` bool, 반환 `(B,F)` int (동결 게임은 -1) |
| `commit(committed, active)` | `(B,F)` bool 둘 다. `committed`의 뜻은 아래 '이동과 확정' 표 |
| `give_reward(R)` | `(B,F)` |
| `on_release(mask)` | **`(B,)` bool, 게임 단위.** 학습 활성은 게임 단위로 시작한다 (TRD 4.5). `ALL_RELEASED`의 fly는 기록용이지 초기화 대상이 아니다. 실행기는 `ALL_RELEASED`가 난 게임 전체에 부른다 |
| `on_eaten(mask)` | `(B,F)` bool |
| `flush_learning(mask)` | `(B,)` bool |
| `reset_life(mask)` | `(B,)` bool |

- **6.1의 8번 호출 순서는 `on_release` → `commit` → `on_eaten`이다.** TRD 6.1의 8번은 `commit` 다음에 `on_release`를 적었다. 그 순서면 같은 틱에서 `ALL_RELEASED` 뒤에 실행된 활성 결정의 흔적이 `on_release`(e = 0)로 지워져 TRD 4.5의 의도와 모순된다. `commit`은 결정별 `active`로 학습을 거르므로 순서를 바꿔도 비활성 결정은 흔적에 들어가지 않는다. **총책임자 결정 — TRD v0.6에 반영할 것.**

### 4.1 이동(moved)과 확정(committed) (점검 F04, 총책임자 승인 2026-11-06 — TRD v0.6에 반영할 것)

`Game.step_flies(actions)`는 `(events, moved, committed, active)`를 돌려준다 (`VecGame`은 `(B,F)`로 쌓는다). 실행기는 `commit(committed, active)`를 부른다. `moved`는 조종기에 넘기지 않는다.

- **`moved[k]`:** 이번 틱에 초파리 k가 실제로 칸을 옮겼다 (집 출구 통과 포함).
- **`committed[k]`:** 이번 틱 6번의 제안 `actions[k]`를 엔진이 초파리 k의 결정으로 받아들였다. 뇌는 흔적 갱신 · 학습 · 증거 초기화를 `committed`가 참인 칸에서만 한다 (TRD 4.7, 10.4). 거짓인 칸의 제안은 버리고 증거 x는 그대로 둔다.
- **결정 지점** (TRD 4.7): ① 이번 틱에 속도 누적으로 이동하고, 현재 칸에 반전 외 선택지가 2개 이상, ② z가 바뀐 다음 틱(반전이 선택지에 더해짐). 결정 지점에서만 `decide`가 참이고 조종기는 행동 ≥ 0을 낸다. 그 밖에는 -1이고 엔진이 유일한 경로를 따른다.

**엔진 구현자는 이 표를 그대로 따른다.** "시험" 열의 *진짜 엔진에서 시험할 것*은 가짜 엔진에 z 변화가 없어 지금 시험이 없다는 뜻이다. 진짜 엔진(팩맨 담당)이 같은 이름의 시험을 만든다.

| # | 경우 | `moved` | `committed` | 비고 | 시험 |
|---|---|---|---|---|---|
| 1 | 결정 지점 ①에서 행동 ≥ 0을 받아 그 방향으로 이동 | 참 | 참 | | `tests/test_committed.py` |
| 2 | 1과 같이 이동한 칸에서 포획됨 | 참 | **참** | 포획은 그 결정의 결과이므로 학습에 들어간다 | `test_runner.py::test_fly_phase_catch_blocks_later_flies_and_rewards_by_regime` |
| 3 | 복도 이동 (행동 -1, 유일한 경로) | 참 | **거짓** | | `tests/test_committed.py` |
| 4 | 집 출구 통과 (방출) | 참 | **거짓** | | `tests/test_committed.py`, `test_engine_fake.py` |
| 5 | 속도가 모자라 이번 틱에 움직이지 않음 | 거짓 | 거짓 | `decide`도 거짓. 다음 틱에 다시 결정한다. 증거 x는 초기화하지 않는다 | `tests/test_committed.py` |
| 6 | 그 초파리 차례 전에 게임이 끝남(앞 초파리의 포획 등) 또는 동결된 게임 | 거짓 | 거짓 | 제안은 버린다 (TRD 10.4) | `tests/test_committed.py`, `test_engine_fake.py` |
| 7 | **지연 반전:** 결정 지점 ②에서 행동 ≥ 0을 받았는데 이번 틱에 움직이지 못함 | 거짓 | **참** | 엔진이 결정을 **절대 방향으로 저장**한 틱에 확정한다. 흔적은 이 틱의 관측 · π로 남는다 | *진짜 엔진에서 시험할 것* |
| 8 | 저장된 지연 반전을 다음 이동 때 적용 | 참 | **거짓** | 확정은 7에서 이미 했다 (두 번 세지 않는다) | *진짜 엔진에서 시험할 것* |
| 9 | 저장된 반전이 기다리는 동안 | (이동 여부대로) | 거짓 | **`decide`를 거짓으로 한다** (결정이 겹치지 않게). 조종기는 -1을 낸다 | *진짜 엔진에서 시험할 것* |
| 10 | 저장된 반전이 적용되기 전에 목숨이 끝남 | — | — | 저장된 반전은 **버린다** (목숨 초기화에서 지움). 7에서 한 확정은 **취소하지 않는다** | *진짜 엔진에서 시험할 것* |
| 11 | 결정 지점 ②에서 그 틱에 바로 이동 | 참 | 참 | 1과 같다 | *진짜 엔진에서 시험할 것* |

- **불변식 (엔진 무관 시험 `tests/test_committed_invariant.py`):** 모든 틱에서 `committed`이면 그 틱 5번 관측의 `decide`가 참이고 6번 행동이 ≥ 0이다. `committed`이고 `moved`가 아니면 지연 반전 저장 틱(행 7)이므로 그 초파리의 `z`가 같은 목숨의 직전 틱 관측과 다르다. 행동 -1이면 `committed` 거짓, 동결 게임은 둘 다 거짓. 연기 설정 한 판을 `engine.kind`별로 돌리며 매 틱 검사한다 (진짜 엔진이 생기면 같은 시험이 그대로 돈다).
- `active`는 지금처럼 "그 초파리가 움직이는 순간(차례)의 학습 활성 값"이다. 7의 경우는 저장한 틱의 값이다.
- 엔진은 받은 행동 ≥ 0이 결정 지점이 아닌 곳에서 왔으면 그 방향으로 움직이되 확정하지 않는다 (가짜 엔진의 구현: `committed = 행동 ≥ 0 이고 반전 외 선택지 2개 이상`).

## 5. 기록기 (recording/recorder.py)

TRD 5.8이 `...`로 비워 둔 인자:

- `Recorder(run_dir, cfg)`
- `on_events(game, events, view)`
- `on_life_end(game, view, events)`, `on_game_end(game, view, events)`: `view`는 초기화 전에 **다시 읽은** 종료 상태 (TRD 6.2). `events`는 그 종료를 일으킨 이번 틱 사건 (`LIFE_LOST`, `GAME_OVER`가 들어 있다).
- `replay_frame(game, views, obs, odor, phero, brain)`: `odor`, `phero`는 `(B,N)`, `brain`은 사전 또는 `None`.
- `replay_end(game, keep)`

`game`은 묶음 안의 게임 칸 번호(0..B-1)다.

## 6. 재생 로그 (replay/schema.py)

- 사건은 세 배열로 저장한다: `ev_tick` `(E,)` int32, `ev_kind` `(E,)` int8, `ev_fly` `(E,)` int8 (초파리 없음 = -1). 사건의 `cause`는 저장하지 않는다 (TRD 19.4는 틱 · 종류 · 초파리만 정함).
- `ev_kind` 정수 코드표 (`schema.KIND_CODES`). **번호를 바꾸거나 지우지 않고, 새 종류는 끝에만 추가한다.**

| 코드 | 종류 | 코드 | 종류 |
|---|---|---|---|
| 0 | CATCH | 6 | GAME_OVER |
| 1 | EATEN | 7 | POWER_START |
| 2 | DOT | 8 | POWER_END |
| 3 | ENERGIZER | 9 | Z_CHANGE |
| 4 | FRUIT | 10 | ALL_RELEASED |
| 5 | LIFE_LOST | | |

- **형식 버전이 2인 이유:** 버전 1은 19.4의 기본 필드, 버전 2는 19.13의 뇌 필드 묶음(`kc_active`, `pn_input`, `mbon_out`, `dan`)을 더한 형식이다. TRD 19.13이 "형식 버전 올림"이라고 했다. 뇌 필드는 전부 있거나 전부 없어야 하므로 뇌 필드가 없는 로그도 버전 2다.
- **형식 버전 3 (M1 뇌 ②, 총책임자 승인 2026-11-08):** 기본 필드 `committed` `(T,4)` bool, `moved` `(T,4)` bool을 **더하기만** 했다 (뜻은 4.1절 표). 실행기가 7번의 값을 `brain` 사전의 `committed`, `moved`로 기록기에 넘긴다 (`replay_frame`의 인자는 그대로). 쓰기는 항상 최신 버전이고, 읽기(`schema.validate`, `reader.read_replay`)는 버전 2와 3을 모두 받는다. 버전 2 파일에는 두 필드가 없어야 하고 버전 3에는 반드시 있다. 버전 2 파일을 읽는 시험을 남긴다 (`tests/test_replay_io.py`). 형식 변경은 시각화 팀과 합의할 것 (README 소유권 표).

## 7. 실행기와 가짜 엔진 (M0 4단계)

- **한 틱 처리와 판 시작 처리는 `core/tick.py`의 `TickCore` 한 곳에만 있다 (관리자 결정 2026-11-08).** 틱 번호(8절), `view.tick` 대조, 사건 틱 다시 쓰기, committed/moved와 조종기 통지 순서(4절), 종료 처리(TRD 6.2), 판마다 난수 갱신(11절)이 모두 여기 있다. 실행기 `Runner`는 `TickCore`를 상속해 부품 조립 · views 규칙 검사 · 무한 루프 감시 · 기록기 닫기만 더한다. PPO 학습 환경도 같은 `TickCore`를 쓴다 (따로 구현하지 않는다).
  - 한 틱은 두 단계다: `views = core.begin()` (1번: views를 만들고 엔진 틱을 대조) → `out = core.finish(팩맨 행동)` (2 ~ 13번과 종료 처리). 순서는 내부 상태로 강제한다: `begin` 없이 `finish`, 또는 `begin`을 두 번 부르면 `RuntimeError`.
  - 콜백 방식(`step(pacman_act)`) 대신 두 단계를 고른 이유: PPO 학습 루프는 관측 → 행동 선택(확률 · 가치를 버퍼에 저장) → 환경 한 스텝의 순서라, 관측을 만든 views와 엔진 틱을 대조한 views가 같은 객체여야 하고 틱마다 views를 한 번만 만든다. 콜백이면 학습 환경이 관측용 views를 따로 만들거나 행동 선택을 콜백 안에 넣어야 한다.
  - 냄새 장(`odor=None`), 기록(`recorder=None`), 체제 보상(`regime=None`)은 인자로 끈다. 끄면 냄새 · 페로몬 관측은 0, 조종기 보상은 0이다. `n_games=None`이면 판이 끝없이 이어진다 (은퇴 없음). `pacman=None`이면 팩맨 이력 초기화와 난수 갱신은 호출자가 한다.
  - `finish`는 `TickOut`(사건, 초기화 전 `now` views, `ends`, `over`, 새로 시작한 칸 `started`, 초파리 행동 · moved · committed)을 돌려준다.

- `Game.index`: 묶음 안의 칸 번호. `VecGame`이 생성 직후 정해 주고, 사건의 `game` 값으로 쓴다.
- `GhostController.uses_views`: 조종기가 `views`를 쓰는지 알리는 표시다. 기본값은 거짓. **`views`를 넘기는 기준은 조건이다: 실행기는 `condition == "b1"`일 때만 넘긴다** (TRD 5.5, 원칙 2). 실행 시작 때 `uses_views != (condition == "b1")`이면 `ValueError`를 낸다. 그래서 `uses_views`만으로 초파리 조건에서 `views`를 받을 수 없다.
- `ALL_RELEASED` 사건 자체의 `active`는 거짓이다 (학습 활성이 켜지기 직전에 만들어진다). 그 뒤 같은 틱에 생긴 사건은 참.
- 판 번호는 1부터. 칸마다 `n_games`판을 한다. 모든 판을 끝낸 칸은 은퇴시킨다: 새 판은 시작하지 않고 `retire`로 `learning_active`만 거짓으로 내리며 동결은 유지한다. **총책임자 결정 — TRD v0.6에 반영할 것** (TRD 6.2의 4번 초기화와 달리 은퇴하는 칸은 판 초기화를 하지 않는다).
- 실행기의 `replay_frame`에는 4번(팩맨 이동 뒤)에 만든 `views`와 5번의 `obs`, 그리고 **5번(관측을 만든 순간)의 냄새 장 · 페로몬 장 복사본**을 넘긴다. 한 프레임의 `views`, `obs`, 냄새 장이 모두 같은 순간이다. 10번의 장 갱신은 이 프레임에 들어가지 않는다. **총책임자 결정 — TRD v0.6에 반영할 것.** 종료 상태는 13번에서 `view`를 다시 읽어 `on_life_end`, `on_game_end`에 넘긴다.
- 조건 `b0`, `b1`은 `NullRegime`(`regimes/null.py`)을 쓴다 (`b0p`는 없앴다, 12.4절): 보상 0, 페로몬 방출 0. 이유: 기준선은 학습하지 않으므로 보상이 없다. 설정에 `reward.p`, `reward.q`가 없어도 만들어진다. 알 수 없는 조건 이름은 `ValueError`다 (이전에는 조용히 `Regime1`이 되었다).

## 8. 기록과 재생 로그 (M0 5단계)

- `GameView`에 기본값이 있는 필드 `pac_acc: float = 0.0`, `fly_acc: (F,) | None = None`을 끝에 더했다. 재생 로그의 보간(TRD 19.6)이 속도 누적값을 쓰기 때문이다. TRD 4.6의 기존 필드는 그대로다.

- **틱 번호의 주인은 실행기 하나다 (관리자 결정 2026-11-08, `ev_tick` 수정).** 실행기(`core/tick.py`의 `TickCore`, 7절 — 실행기와 학습 환경이 같이 쓴다)는 칸마다 현재 판의 틱 번호 `tick_no`를 갖는다. 동결된 틱(목숨을 잃은 틱 포함)을 포함해 진행 중인 칸은 매 틱 올리고, 새 판에서 0으로 돌린다. 엔진이 돌려준 사건(3 · 7 · 9번)의 틱 번호는 실행기가 이 값으로 다시 쓴다. 엔진의 `view.tick`(감시 장치가 쓰는 번호)은 실행기의 번호를 따라야 하며, 실행기가 매 틱 1번(`begin`)에서 대조해 다르면 `RuntimeError`로 멈춘다. 그래서 엔진도 **동결된 틱에 틱 번호를 올린다** (`tick_timers`).
  - 고친 문제: 가짜 엔진의 `tick_timers`가 동결된 틱에 번호를 올리지 않아, 판 도중 목숨을 잃을 때마다 `ev_tick`이 프레임 번호보다 1씩 작아졌다 (예: 프레임 399개인 판의 마지막 `ev_tick`이 397). `games.csv`의 `틱 수`(종료 상태의 `view.tick`)도 같이 모자랐다. 이제 `틱 수` = 그 판의 프레임 수다.

### 10.1 미결 2: PN 채널 · MBON 묶음 배정 (해결)

- 배정은 프로젝트가 부여한 대응이다. 생물학적 근거를 주장하지 않는다.
- 학습 전 방향 편향은 **기준선 빼기**(10.3)로 구조적으로 없앤다. 배정은 편향을 최적화하지 않고 **표현력**만 시험한다.
- 규칙 1 (선택): 주석으로 정의하고 연결로 선별한다. 한 번 통과, 반복 제거 없음 (10.6).
- 규칙 2 (MBON 4묶음, 시드와 무관하게 한 번): $w^{(0)}_{ij} = W_{0,ij} / \langle W_0\rangle_{W_0>0}$, $T_{a\tau} = \frac{1}{|a|}\sum_{j\in a}\sum_{i\in\tau} w^{(0)}_{ij}$. 묶음 좌 · 직진 · 우 · 반전, 크기 차이 ≤ 1. 각 KC 종류 $\tau$에서 $T_{a\tau}$의 네 묶음 간 상대 편차의 최댓값을 최소화한다. 고정 시드 탐욕 배정 → 맞바꾸기 국소 탐색, 탐색 횟수는 설정에 고정.
- 규칙 3 (PN 9묶음, 시드마다): 채널 순서 냄새 좌 · 앞 · 우 · 뒤, $z$, 페로몬 좌 · 앞 · 우 · 뒤. 단위는 사구체(같은 사구체의 PN은 같은 채널). 분기 P(기본): DA1, VA1v, VA1d, DL3를 페로몬 4채널에 하나씩, 방향은 시드로 무작위, 나머지 사구체를 냄새 4 + $z$에 무작위 분할. 분기 G(대안): 모든 사구체를 9채널에 무작위 분할. 사구체 수는 채널 간 최대 1 차이. 시드는 0 ~ 19로 고정하고 결과를 본 뒤 바꾸지 않는다. $J_{ic} = \sum_{p\in c} J^{\text{pn}}_{ip}$.
- 규칙 4 (채널 이득): $S_c = \sum_i J_{ic}$, $\alpha_c = \bar S / S_c$. $S_c = 0$이면 그 시드는 실패로 기록한다 (예외로 멈추지 않음).
- 규칙 5 (분기 P 전환, 사전 확정): (1) 후보 사구체 중 하나라도 규칙 1을 통과하지 못함, (2) 네 페로몬 채널의 도달 KC 수 max/min > 1.5, (3) 다음 지시서의 표현력 시험에서 분기 P로 시드 0 ~ 19를 모두 검사한 뒤 통과 시드가 없음. 하나라도 참이면 분기 G.

### 10.3 기준선 빼기 (**TRD v0.6에 반영할 것**, 구현은 다음 지시서)

$$
m_a = \frac{1}{k\,|a|}\sum_{j\in a}\sum_i \big(w_{ij}-w^{(0)}_{ij}\big)\,k_i
$$

- TRD 10.4의 흔적 · 갱신식은 그대로다 ($\partial x_a/\partial w_{ij} = h_i/(k|a|)$ 유지).
- $w^{(0)}$은 회로 파일에서 읽는 **불변 참조 배열**이다. 네 초파리가 읽기 전용으로 공유한다.
- 체크포인트에 회로 파일 해시를 저장하고, 재개할 때 대조한다.
- 설명 문구: "인위적으로 부여한 방향 대응에서 나오는 초기 정책 기여를 연구 대상에서 제외한다. 연결 구조가 표현과 학습에 미치는 영향은 유지한다." 생물학 설명은 "인공 판독 규칙".

| $\theta_{\text{KC}}$ | 0.8 (아래 정의 A) | 본 칼릭스에서 s_min 정리 후 PN 계열 시냅스 수 중 선택 PN의 몫이 80% 이상. 시냅스 수 비율이며 생리적 구동의 비율은 아니다 |
| KC 최소 입력 (**새 기준**) | 선택 PN에서 받는 본 칼릭스 시냅스 ≥ 20 | 비율만 높고 입력이 거의 없는 KC를 거름 |
| $\theta_{\text{MBON}}$ | 100 (선택 KC에서 받는 시냅스, 꽃자루 + 15구획) | 조각난 재구성을 거르고 작지만 진짜인 MBON은 남김 |

- **적용 순서 (총책임자 결정 2026-11-06, PR #5 검토):** $s_{\min}$으로 연결 단위 정리를 맨 먼저 하고, $\theta_{\text{PN}}$ · $\theta_{\text{KC}}$ · KC 최소 입력 · $\theta_{\text{MBON}}$은 정리된 시냅스 수로 계산한다. 지시서 4.1이 $s_{\min}$을 6번(마지막)에 적은 순서가 모호했던 것을 바로잡는다. 정리는 후보 전체에 적용한다 (PN 계열 → 후보 KC는 본 칼릭스, 후보 KC → 후보 MBON은 꽃자루 + 15구획 합). 그래서 $\theta_{\text{KC}}$의 분모도 정리된 값이다.

- **제외:** vPN 계열, `Z_`, VP 온습도, 다사구체(VP 포함 다사구체 포함). **포함:** 단일 사구체 V, D.
- **lvPN 계열은 포함하며 흥분성으로 가정한다 (서버 미확인).** hemibrain v1.2.1 서버에는 전달물질 주석이 없어 확인하지 않았다. 지시서 4.1의 "PN은 흥분성"($J \ge 0$) 가정을 따른다.
- KC는 종류 이름으로 빼지 않는다. 문턱이 거른다. 결과: KCg-d 99개 중 5개, KCab-p 60개 중 0개, KCg-s1 ~ s4 각 1개 중 0개가 남았다.
- MBON은 instance의 좌우와 관계없이 $\theta_{\text{MBON}}$으로만 거른다. `MBON15-like`, `MBON17-like`를 포함한다.
- 정의 A (KC 비율): 분자 = 본 칼릭스에서 **선택 PN**에게서 받는 (정리된) 시냅스. 분모 = 본 칼릭스에서 **이름에 PN이 들어간 모든 뉴런**에게서 받는 (정리된) 시냅스 (배제한 온습도 · 다사구체 · vPN 포함, APL · DPM · KC · 주석 불명 제외). WEDPN · LPN은 본 칼릭스 → KC 시냅스가 0이라 분모에 넣어도 값이 같다.
- 결과 (`data/circuit/raw/mb_raw_v1.meta.json`): PN 461 → 후보 145 → 106, KC 1,927 → 1,575, MBON 71 → 47. 사구체는 주석 후보 51 (θ_PN 적용 전) → 원본 51 (θ_PN 적용 후). θ_PN에서 탈락한 39개 PN은 모두 같은 사구체의 다른 PN이 남아 사구체 수는 줄지 않았다.

### 10.8 구현에서 정한 해석 (지시서 · TRD 문구에 없거나 다르게 한 곳)

- **ROI 이름** (hemibrain v1.2.1 서버 확인): 본 칼릭스 `CA(R)`, 부속 칼릭스는 `dACA(R)`, `lACA(R)`, `vACA(R)` 세 개(`MB(R)` 밖), 꽃자루 `PED(R)`, 엽 구획 `a1(R)` ~ `g5(R)` 15개(non-primary라 `include_nonprimary=True`로 조회), 외측뿔 `LH(R)`. 15구획 합은 5엽 합과 같다.
- **PN 분류 규칙:** `WEDPN*`, `LPN`은 더듬이엽 밖 PN이라 단일 사구체 후각 PN 후보가 아니다 (제외 목록이 아니라 후보 정의로 빠짐, 칼릭스 입력도 0). 다사구체 = `M_` · `MZ_` 접두 또는 사구체 이름에 `+`. 계열 = `_` 뒤의 `…PN`. vPN 제외는 계열 이름이 정확히 `vPN`인 것만이다 (`lvPN`은 흥분성 가정으로 포함, 서버 미확인 — 10.6). 사구체 = 종류 이름의 첫 `_` 앞.
- **$s_{\min}$은 맨 먼저 적용한다** (10.6). PR #5의 첫 판은 4.1의 문구대로 마지막에 적용해 KC 1,579, MBON 50이었다. 순서를 바꾼 뒤 KCab-c 5개가 빠지고 KC 1개가 새로 들어왔으며, MBON 3개(MBON10 613719036, MBON11 517518166, MBON34 1173814525)가 빠졌다. PN은 그대로다.
- **`mbon_class_profile`**: 선택 KC 기준 (W0의 열을 KC 종류별로 더한 비율). **`mbon_class_profile_candidates`**: 모든 후보 KC에서 받는 시냅스(꽃자루 + 15구획, $s_{\min}$ 정리 뒤) 기준. 열 순서 `gamma`, `apbp`, `ab` (`kc_class`의 값과 같음).
- **파일 이름:** 원본은 `data/circuit/raw/mb_raw_v1.npz`다. TRD 10.1의 `mb_v1.npz`(최종 회로)는 다음 지시서에서 표현력 시험을 통과한 시드로 만든다.
- **KC → MBON 계수는 꽃자루 + 15구획만**이다. 칼릭스 MBON(`MBON22`)의 칼릭스 입력은 들어가지 않는다.
- **정면 투영 축:** hemibrain 좌표에서 `y`가 앞뒤, `z`가 등배(작을수록 등쪽), `x`가 좌우다. 투영 $(u, v) = (+x, -z) \times 0.008\,\mu\text{m}$ (복셀 8 nm, 서버 Meta와 대조). 앞에서 본 모습이라 오른쪽 버섯체의 정중선 쪽이 $+u$다. 가설을 설정에 적고 확인 시험으로 검증했다: (가) α엽 끝 > 뿌리, (나) β엽 끝이 뿌리보다 정중선(EB 중심)에 가까움, (다) 칼릭스 > 뿌리, (라) 칼릭스–뿌리 차이가 가장 큰 축 = 버린 축. 모두 통과.
- **기준점:** 뿌리 = 꽃자루 메시 중 칼릭스 중심에서 가장 먼 5% 꼭짓점의 평균 (엽이 갈라지는 쪽 끝). α · β엽 끝 = 각 엽 메시 중 뿌리에서 가장 먼 5%의 평균. 정중선 = EB 메시 중심.
- **영역 다각형:** shapely 대신 새 의존성 없이 만든다. 삼각형을 0.5 μm 격자에 칠하고 3×3 닫힘 → 경계 추적 → Douglas–Peucker(허용 오차 0.5 μm), 4 μm² 미만 고리는 버린다. 칼릭스 영역은 본 칼릭스 `CA(R)`만이다 (부속 칼릭스는 그리지 않음).
- **DAN:** 이름 규칙(`PAM*`, `PPL1*`)의 317개 전부 (instance 좌우 무관). 좌표 = 15구획 안 시냅스 전 위치 중심, 구획 = 시냅스 전 위치가 가장 많은 구획. 15구획에 시냅스 전 위치가 없는 2개는 좌표 없음(이유 기록).
- **MBON 묶음 탐욕 배정:** 시드로 섞은 순서대로, 자리가 남은 묶음 중 목적값(최종 묶음 크기로 나눈 평균 기준)이 가장 작은 곳에 넣는다. 국소 탐색은 매 회 가장 좋은 쌍 맞바꾸기 하나를 받아들인다. 목적값 1.029 → 0.068 (맞바꾸기 23회).
- **채널 무작위 분할:** 어느 채널이 사구체를 하나 더 받는지도 시드로 무작위다 (앞 채널에 몰리지 않음). 난수는 `np.random.default_rng(seed)`.
- **접합 KC 비율:** 냄새 채널 하나 이상과 $z$ 채널에서 모두 입력을 받는 KC의 비율 (`J_ic > 0` 기준).

### 12.1 `propose` 계약 변경 (**TRD 5.5의 수정 — TRD v0.6에 반영할 것**)

> `propose`는 틱당 한 번 감각 증거($x$, $h$)를 누적하고, 결정 시점이면 $(\pi, a_*, L)$를 보관한다. 학습 상태($w$, $e$, $\bar R$, $R_n$)는 바꾸지 않는다. 같은 틱의 중복 호출은 허용하지 않는다 (오류).

- 이유: TRD 5.5는 `propose`가 "상태를 바꾸지 않는다"고 했지만 TRD 10.3은 증거를 매 틱 쌓는다. 실행기가 매 틱 부르는 조종기 메서드는 `propose`와 `commit`인데, `commit` 전에 결정이 증거를 읽어야 하므로 누적은 `propose`에 둔다. `brain/base.py`의 docstring을 이 문장으로 고쳤다. 메서드 이름 · 인자 · 반환 모양은 그대로다.
- **중복 호출 감지:** `propose`는 틱 번호를 받지 않는다. 깃발 하나(조종기 전체)를 `propose`가 세우고 `commit`이 내린다. 깃발이 선 채 `propose`를 다시 부르거나, `propose` 없이 `commit`을 부르면 `RuntimeError`. 실행기는 매 틱 `commit`을 부른다 (모든 칸이 거짓이어도).
- 동결된 게임(`alive` 거짓)은 아무것도 갱신하지 않고 $-1$을 돌려준다.
- **누적 대상: 살아 있는 게임의 네 마리 모두, 집 안 · 방출 전 포함, 매 틱.** 근거: TRD 10.4 "활성이 시작되는 순간 $x$, $h$ 유지 … 출발 전에 맡은 냄새는 첫 활성 결정에 쓴다." 출발 전에도 쌓아야 이 문장이 성립한다.
- `commit`에서 `committed`가 참인데 보관한 제안이 없으면 `ValueError` (엔진 계약 위반을 일찍 잡는다).
- `flush_learning(mask)`는 학습 활성 값을 인자로 받지 않으므로, 뇌는 **마지막 `commit`의 `active`**(그리고 `on_release`)로 초파리별 활성을 기억해 쓴다. 종료 처리는 같은 틱의 `commit` 뒤에 오므로 그 값이 "활성 플래그가 아직 유지된 상태"다.

### 12.2 결정 시점 두 종류와 가짜 엔진 확인 결과

| 종류 | `decide`가 참인 조건 | 속도 부족 |
|---|---|---|
| ① 보통 갈림길 | 속도 누적기가 **이번 틱에 이동을 일으키고**, 반전 외 선택지 ≥ 2 | 정의상 일어나지 않는다 |
| ② 반전 기회 | 파워 시작 · 종료로 $z$가 바뀐 뒤 처음 오는 초파리 결정 단계(6.1의 6번). 파워 시작은 같은 틱, 파워 종료는 다음 틱 | 저장한 틱에 확정 (4.1절 7 ~ 11행). 예약을 적용하는 틱에는 다시 확정하지 않는다 (`moved`만 참) |

- **확인 결과 (2026-11-08): 가짜 엔진은 ①의 정의대로다.** `FakeGame.decision_info()`는 `decide = 반전 외 선택지 ≥ 2 그리고 fly_acc + v_fly ≥ 1 그리고 동결 아님`이고, `_move_fly`가 같은 덧셈으로 이동을 정한다. 연기 설정(시드 4개 × 3판)을 속도 1.0, 0.9, 0.8, 0.75, 0.6, 0.5, 1/3, 0.3, 0.1로 돌려 모든 결정 틱을 보았다: `decide` 참이고 이동하지 않은 경우는 **앞 초파리의 포획으로 그 차례 전에 게임이 끝난 2건뿐**이었다. 4.1절 표의 5행("속도 부족 → 둘 다 거짓, 제안 버림")은 결정 틱이 아닌 경우(행동 −1)에만 지나는 방어 분기다.
- 그래서 불변식 시험(`tests/test_committed_invariant.py`)에 더했다: 반전 기회가 아닌(같은 목숨에서 $z$가 직전 틱과 같은) 결정 틱에서 `decide`이면, 그 초파리의 이동 차례까지 게임이 끝나지 않았을 때 그 틱에 `moved`. 이동 단계 도중 포획(`CATCH`)으로 끝난 게임은 잡은 초파리보다 뒤 번호만 예외다. 무작위 초파리와 초파리 뇌 둘 다로, 속도 1.0 · 0.75 · 0.6에서 돈다. 가짜 엔진의 `decide`에서 속도 조건을 빼면 이 시험이 실패하는 것을 확인했다.
- 반전 예약의 **뇌 쪽**(적용 틱에 `committed` 거짓이면 흔적 · 학습이 다시 일어나지 않음)은 `tests/test_flybrain.py`에서 시험한다. **엔진 쪽**(저장 · 적용 · 대기 · 목숨 끝 폐기)은 *진짜 엔진에서 시험할 것* (4.1절 표 그대로).

### 12.3 순방향 · 출력 · 학습 구현

- 채널 순서 냄새 좌 · 앞 · 우 · 뒤, $z$, 페로몬 좌 · 앞 · 우 · 뒤. **채널 이름은 `assign.channel_names()`가 `core.directions.EGO_NAMES`에서 만든다** (Codex F10).
- $\tilde p_c = \alpha_c p_c$, $u = J\tilde p$, $k_i = \mathbb 1[u_i > \theta \wedge u_i \in \text{상위 } k]$, $k = \lceil \rho N_{\text{KC}}\rceil$. $\alpha_c$는 PN 입력 사본에만. 상위 $k$ 경계의 동률은 게임별 난수(용도 `"kc_tiebreak"`)로 끊고, $u$에 잡음을 더하지 않는다. 난수는 경계에 동률이 실제로 걸린 행에서만 뽑는다. 한 게임의 네 초파리는 초파리 번호 순서로 같은 생성기를 쓴다.
- $m_a = \frac{1}{k|a|}\sum_{j\in a}\sum_i (w_{ij}-w^{(0)}_{ij})k_i$ (10.3절). **학습 상태는 변화분 $dw = w - w^{(0)}$ 하나뿐이다** (PR #7 검토, 총책임자 결정 2026-11-08). 갱신은 $dw \leftarrow \max(dw + \Delta w,\, -w^{(0)})$이고 이것이 $w \ge 0$과 같다. $w$가 필요하면(시각화 등) $w^{(0)} + dw$로 만든다. 그래서 $w = w^{(0)}$이면 $m_a$가 정확히 0이다. $w^{(0)}$은 회로 하나에 읽기 전용 배열 하나 (`setflags(write=False)`)이고 $dw$와 메모리를 공유하지 않는다.
- 결정: $\pi_a \propto e^{\beta x_a}$ (합법 행동만), $a_* \sim \pi$ (용도 `"brain_action"`). 확정 · 학습은 TRD 10.4 그대로 (1 · 2는 활성일 때만, 3은 항상).
- 배열은 float64다 (12.6의 메모리 참고). float64를 유지한다 (총책임자 결정 2026-11-08).
- 단계 1 · 2의 회로 값은 **자리표시**다: 배정 시드 0, $\rho = 0.05$, $\theta = 0$ (`configs/brain_v1.yaml`). 단계 3 선정 결과로 바꾸고 커밋 메시지에 "단계 3 선정 결과 반영"을 적는다. $\kappa, g, \beta, \eta, \alpha, \gamma$는 미결 4의 자리표시 (0.2, 1.0, 1.0, 0.01, 0.01, 0.9).

### 12.4 B0와 `b0p` 제거

- **B0 = 같은 코드, $w = w^{(0)}$에서 시작하고 $\eta = 0$.** 조건 `b0`이면 뇌가 $\eta$를 0으로 강제한다. 학습된 $w$를 불러와 $\eta = 0$으로 둔 정책은 B0가 아니다 (학습 후 평가용 고정 정책): 조건 `b0`에서 $w \ne w^{(0)}$인 상태를 불러오면 `ValueError`. 기준선 빼기로 학습 전 버섯체 출력이 0이므로 TRD의 "본능만($m_a = 0$)"과 같다.
- 본 실험은 5조건 (체제 1 · 2 · 3, B0, B1). **`b0p`는 오류**다 (`make_regime`, `FlyBrain` 둘 다). 실수로 6조건이 되지 않게 한다.

### 12.5 난수 · 저장 · 재개

- 용도 번호를 뒤에 덧붙였다: `kc_tiebreak` 6, `brain_action` 7, `repr_synth` 8 (11절 규칙).
- 용도가 여럿인 조종기를 위해 `core.rng.RngGroup`(용도 → `GameRngs`)을 더했다. 실행기는 `GameRngs`와 같이 새 판마다 `renew(mask, game_no)`를 부른다 (`isinstance(bundle, (GameRngs, RngGroup))`).
- **난수는 판마다 다시 만들지만 $w$와 $\bar R$은 판을 넘어 이어진다.** 목숨 · 판 경계의 `reset_life`는 $x, h, e, R_n$만 비운다. 시험으로 고정했다 (`test_runner_carries_w_and_rbar_across_games_and_renews_rngs`).
- `state_dict()`: **`dw`만** (w는 저장하지 않는다), `rbar`, 난수 상태(용도별), 칸별 판 번호, **회로 파일 해시**(원본 `mb_raw_v1.npz`의 sha256)와 배정 시드, 설정 해시, 조건, 설정 변경 허용 기록(`config_changes`). $w^{(0)}$은 저장하지 않고 회로 파일에서 다시 만든다. 이유: 상태를 하나로 두면 $w$와 $dw$가 어긋날 수 없고, $w$에서 $w^{(0)}$을 다시 빼는 부동소수점 반올림 때문에 재개가 끊지 않은 실행과 달라지는 일도 없다 (재개 시험 유지). 저장 형식 번호는 2.
- `load_state_dict()`는 회로 해시나 배정 시드가 다르면 `ValueError`로 멈춘다.
- **설정 해시도 대조한다 (총책임자 결정 2026-11-08).** 다르면 `ValueError`로 멈춘다. 이유: 본 실험 재개 중 설정이 바뀌면 한 실험의 앞뒤가 다른 조건이 되는데, 결과 파일에는 드러나지 않는다. 의도한 변경은 **명시적 인자 `load_state_dict(state, allow_config_change=True)`로만** 허용한다. 허용하면 경고를 내고, 허용한 사실과 두 해시(저장 · 현재)와 판 번호를 `config_changes`에 남긴다. 이 기록은 이후 `state_dict()`에 따라가므로 같은 실험의 다음 체크포인트에도 남는다. 재개 실행 명령(아직 없음)을 만들 때는 같은 뜻의 옵션 `--allow-config-change`를 두고 이 기록을 결과 폴더에도 쓴다.
- **재개 설계 (관리자 결정 2026-11-08, 구현은 재개 명령을 만들 때):** 난수가 (시드, 판 번호, 용도)로 결정론적이고 재개는 판 경계에서만 하므로, 체크포인트에는 **판 번호만** 두고 재개할 때 **다음 판 번호로 난수를 새로 만든다.** 재개 명령을 만들 때 `run()`(실행기 `start`)에 **시작 판 번호 인자**를 둔다 (지금 `start`는 모든 칸을 판 1로 시작하고 조종기 난수도 판 1로 다시 만든다). 그때 `FlyBrain.state_dict()`의 난수 상태 저장은 판 번호만 남기도록 정리한다 (지금은 용도별 난수 상태를 저장한다).
- **재개는 판 경계에서만** (TRD 13.6). 불러오면 $x, h, e, R_n$과 보관한 제안을 비운다. 임의 틱 재개는 지원하지 않는다.

## 13. 표현력 시험과 시드 선정 (M1 뇌 ② 단계 3, 총책임자 승인 2026-11-08)

**13.1 ~ 13.9는 작업 지시서(판 3) 4절을 그대로 옮긴 것이다. 4절은 동결이며, 측정 결과를 본 뒤 바꾸지 않는다.** 이 절은 측정 코드를 쓰기 전에 커밋한다. 소제목의 `(지시서 4.n)`은 원문의 번호이고, 본문 안의 "4.n절" 참조는 모두 이 절의 13.n을 가리킨다 (예: "4.5의 표본 수 조건" = 13.5). "5절"은 지시서의 단계 4(최종 검증)이다.

### 13.1 (지시서 4.1) 목적과 해석의 한계

배정 시드 0 ~ 19 중, KC 표현에서 과제에 필요한 정보를 **자유 선형 판독기로 해독할 수 있는** 회로를 사전 순서대로 고른다. 뇌 가중치는 고정하고 진단용 분류기만 학습한다.

- 통과의 뜻: "이 자료 분포에서, 자유 선형 판독기로 해독 가능." 실제 판독(행동별 연결 제약, $w - w^{(0)} \ge -w^{(0)}$, 편향항 없음) 아래의 학습 가능성은 작은 과제 A ~ D가 판정한다.
- 실패의 뜻: 정보가 없다는 증명이 아니다. 자료 부족 · 정규화 · 비수렴일 수 있으므로 **실패 이유를 구분해 기록**한다.
- 선정 결과는 "최적 회로"가 아니라 **"사전 우선순위에서 처음 통과한 회로"**다.

핵심 우려 (Codex G2): 표현이 $\phi(\mathbf o, z) \approx f(\mathbf o) + g(z)$꼴이면 선형 판독으로 "$z$에 따라 방향을 뒤집는" 과제 C를 풀 수 없다. 시험 4가 이것을 통제된 자료로 직접 본다.

### 13.2 (지시서 4.2) 자료 생성 (사전 고정)

**원천 관측.** 가짜 엔진 + 진짜 냄새 장 · 감각 + 무작위 유령으로 실행기를 돌린다.

| 항목 | 값 |
|---|---|
| 실행 시드 하나 | 게임 10판 (`game_rngs`로 판별 난수), 판당 상한 3,000틱 |
| 저장 | **모든 틱**의 `FlyObs`, 결정 시점 표시, 확정 · 초기화 시점 (누적 $\mathbf h$ 보조 시험에 필요) |
| 합성 난수 | `game_rngs`의 용도 `"repr_synth"`. 자료 생성기 버전을 meta에 |
| 같은 자료 | **모든 시드 · 격자가 같은 자료**를 쓴다. 분할별 자료 해시를 기록 |

**분할 (판 단위).**

| 분할 | 실행 시드 | 용도 |
|---|---|---|
| 개발-학습 | 1000 ~ 1013 | 분류기 학습, **냄새 중앙값 계산** |
| 개발-평가 | 1014 ~ 1019 | 선정 중 합격 판정 |
| 최종 검증 | 2000 ~ 2009 | 후보 하나에 한 번 |

합성 표본은 원천과 같은 분할에 둔다. 결과를 본 뒤 분할 · 생성 설정을 바꾸지 않는다.

**공통 정의.**
- 결정 표본: `decide`가 참이고 **$|L| \ge 2$**인 틱. $|L| = 1$은 KC 없이도 맞히므로 판정에서 뺀다.
- 동률: 로그 변환 후 값의 차이 $\le 10^{-6}$.
- 유일 표본: 해당 시험의 최적 행동 집합 크기가 1.
- 구배 표시 (보고용): 합법 행동 중 최댓값 $o_{(1)}$, 두 번째 $o_{(2)}$에 대해 $r = (o_{(1)} - o_{(2)}) / o_{(1)}$. 약함 $r < 0.1$, 강함 $r \ge 0.3$.
- 제외 비율 표시: $|L| < 2$, 동률, 무입력으로 빠진 표본의 비율을 시험마다 보고한다.

### 13.3 (지시서 4.3) 시험

**시험 1. 냄새 방향.** 원천 관측($z = 0$, 페로몬 0). 정답 $\arg\max_{a \in L} o_a$. 지표: 방향별 균형 정확도.

**시험 2. 상태.** 원천 관측마다 $z$만 0 ↔ 1로 바꾼 짝. 짝은 냄새 · 페로몬 · $L$을 공유한다. 정답 $z$. 지표: 균형 정확도.

**시험 3. 페로몬 채널의 방향 전달.** 원천 관측에, **같은 $L$과 같은 자기중심 벽 마스크**를 가진 다른 원천 관측의 냄새 패턴을 페로몬으로 넣는다 (같은 분할 안에서, `"repr_synth"` 난수로 짝지음). $L$이 거짓인 이유는 벽만이 아니라 반전 금지도 있으므로 벽 마스크를 따로 맞춘다. 벽 마스크는 자료 생성용 메타데이터로만 보관하고 뇌 · 분류기 입력에 넣지 않는다. 냄새와 페로몬의 통계적 독립까지 보장한다고 주장하지 않는다. 정답 $\arg\max_{a \in L} \phi_a$. 지표: 방향별 균형 정확도. "냄새와 같은 방향 · 다른 방향" 구분은 **합법 행동 안의 실제 최적 방향**으로 판정해 따로 보고한다.
- 이 시험은 "페로몬 채널이 방향 정보를 KC로 전달하는가"만 본다. 체제 3의 실제 페로몬 분포에 대한 검증이 아니다 (4.8).

**시험 4. 과제 C 결합 (통제 자료).** 원천 관측 중 $|L| \ge 2$이고 합법 행동 안에서 최댓값 방향 $A$와 최솟값 방향 $B$가 **각각 유일하고 서로 다른** 표본을 기본으로 삼는다. 기본 하나에서 네 변형을 만든다.

| 변형 | 냄새 | $z$ | 정답 |
|---|---|---|---|
| 원본 · 평소 | 원본 | 0 | $A$ |
| 원본 · 겁먹음 | 원본 | 1 | $B$ |
| 교환 · 평소 | $o_A$와 $o_B$를 맞바꿈 | 0 | $B$ |
| 교환 · 겁먹음 | 같음 | 1 | $A$ |

- 네 변형은 같은 분할, 같은 $L$을 쓴다. 페로몬 0. 다른 합법 방향의 값은 그대로 둔다 (교환 뒤에도 $B$가 유일 최대, $A$가 유일 최소이므로 정답은 정확히 $A, B, B, A$).
- 의미: 네 변형은 **합성 감각 입력**이다. 실제 냄새 장에서 실현 가능한지는 요구하지 않는다. 상태에 따른 방향 선택의 결합 표현만 검사한다.
- 지표: $z$별 **방향 균형 정확도** (둘 다 판정). 보조: 기본 하나의 네 변형을 **모두** 맞힌 비율 (기록).
- 실제 관측(통제 없음)의 과제 C 정확도도 기록한다 (판정에 안 씀).

**대조 분류기 (자료 구성 검사).** KC 없이 $z$와 합법 마스크만 입력으로 같은 분류기를 학습한다.
- 완전한 네 변형 묶음에서는 같은 $(z, L)$의 두 변형(원본 · 교환)의 정답이 서로 반대다. 그래서 $(z, L)$만 보는 결정론적 분류기는 둘 중 하나만 맞힌다. **일반 정확도의 상한이 정확히 0.5**다.
- 검사: 완전한 네 변형 묶음을 같은 가중치로 평가한 **$z$별 일반 정확도 ≤ 0.50**. 예측 동률은 결정론적으로 처리한다. 넘으면 **자료 구성 코드의 버그**다. 회로를 판정하지 않고 멈추고 보고한다.
- 대조의 균형 정확도는 기록만 한다 (방향별 표본 수가 다르면 0.5를 넘을 수 있어 판정에 쓰지 않는다).
- 대조는 회로 · 격자와 무관하다. **자료 분할당 한 번** 계산하고 180개 조합에서 그 결과를 참조한다.
- 시험 1 · 3의 대조(마스크만)도 기록한다 (판정에 안 씀).

### 13.4 (지시서 4.4) 분류기 (사전 고정)

- scikit-learn `LogisticRegression`: `solver="lbfgs"`, L2, `C=1.0`, `class_weight="balanced"`, `max_iter=2000`, `tol=1e-4`, `fit_intercept=True`, `random_state=0`.
- **주 판정 입력: MBON에 연결된 KC** ($\sum_j M_{ij} > 0$)의 순간 활동 $\mathbf k$.
- 예측: 결정 함수의 합법 행동 중 최댓값 (마스크 적용). 분류기에게 합법성을 맞히게 하지 않는다.
- 학습: 해당 시험의 유일 표본만. 평가: 유일 표본으로 판정, 부분 · 완전 동률은 따로 보고.
- **비수렴**(수렴 경고)은 그 시험의 실패로 기록하되, 실패 이유를 "분류기 비수렴"으로 구분한다.
- scikit-learn은 선택 의존성 그룹 `analysis`로 추가 (관리자 승인 완료). 2주 이상 된 안정판으로 정확히 고정. 기본 설치와 CI에는 넣지 않는다.

**보조 결과 (후보 하나에 대해서만, 판정에 안 씀).**
- ① 모든 KC를 입력으로 쓴 결과 (정보가 어디까지 남아 있는가).
- ② 누적 $\mathbf h$ ($\kappa \in \{0.1, 0.2, 0.5\}$). 실제 결정은 $x_a$가 $\mathbf h$에 선형이므로 $\mathbf h$의 판독이다. 저장한 전체 틱 이력에서 확정 · 초기화 시점을 재현해 계산한다. 합성 $z$는 **직전 초기화 이후 구간 전체**에서 바꾼다.

### 13.6 (지시서 4.6) $(\rho, \theta)$ 격자 (사전 고정)

- $\rho \in \{0.05, 0.02, 0.10\}$ (이 순서).
- $\theta = c \cdot \bar u_{\text{ref}}$, $c \in \{0, 1, 2\}$ (이 순서). $\bar u_{\text{ref}}$: 기준 입력(냄새 네 채널 = **개발-학습 자료만으로 계산한** 냄새 중앙값, $z = 0$, 페로몬 0, $\alpha_c$ 적용)에서 KC 전체 $u_i$의 평균. 시드마다 계산해 고정한다. 최종 검증에서 다시 계산하지 않는다.

### 13.7 (지시서 4.7) 측정과 선정 (사전 고정)

**측정과 선정을 분리한다.**

1. **측정**: 시드 0 ~ 19 × 격자 9개 = 180개 조합을 **모두** 평가하고 기록한다 (시험 1 ~ 4, 대조, 실패 이유).
2. **선정**: 사전 순서(시드가 바깥, 격자가 안쪽)에서 **처음으로** 시험 1 ~ 4를 모두 통과한 조합 하나를 후보로 한다.
3. 후보가 없으면 멈추고 설계 재검토를 보고한다.

- **통과 시드 수** = 격자 9개 중 하나 이상에서 시험 1 ~ 4를 모두 통과한 배정 시드의 수. "통과 시드 수 / 20"을 보고한다. 결과가 특정 배정에 얼마나 의존하는지의 지표다.

- **선정된 회로를 모든 체제와 기준선에 똑같이 쓴다.**

### 13.8 (지시서 4.8) 나중 검증의 규칙 (지금 고정)

| 검증 | 언제 | 내용 | 실패 시 |

**진짜 엔진 분포 검증의 방식.**

### 13.10 구현에서 정한 해석 (측정 전 기록, 관리자 승인 2026-11-08)

지시서 4절이 정하지 않았거나 가짜 엔진 때문에 구체화가 필요한 곳을 **측정 전에** 고정한다. 결과를 본 뒤 바꾸지 않는다.

1. **자료 생성 설정 `configs/brain_repr_v1.yaml`** (`configs/`는 관리자 소유, 승인됨). 엔진 · 냄새 · 방출 시점은 `m0_smoke.yaml`의 자리표시 값. 조건 `regime1` (페로몬 장 없음, 페로몬 관측 0), 유령은 무작위. 실행 시드 하나에 `n_games: 10`, 판당 상한 3,000틱은 `engine.watchdog_ticks: 3000` (CENSORED로 끝남). 자료 생성기 버전 `repr_data_v1`.
2. **틱마다 저장하는 것** (초파리별): 냄새 `(4)`, `z`, `legal (4)`, `decide`, `committed`, 동결 여부, **자기중심 벽 마스크 `(4)`** (그 칸의 초파리 이동 마스크를 진행 방향으로 돌린 것), 초기화 시점(목숨 끝 · 먹힘 · 방출). 기록기 인터페이스로 모으고 분할별 sha256을 기록한다.
3. **결정 표본** = `decide` 참, $|L| \ge 2$, 동결 아님.
4. **기준 입력의 냄새 중앙값 (13.6의 $\bar u_{\text{ref}}$)**: 채널마다, 개발-학습 결정 표본에서 **그 방향이 열려 있을 때(벽 마스크 거짓)의 값만**으로 중앙값을 낸다. 벽의 0은 제외한다. 이유: "합법일 때만"으로 하면 반전이 금지된 뒤 채널은 열린 통로라 냄새가 실제로 들어오는데도 값이 거의 남지 않아 중앙값을 낼 수 없다. 합법성은 행동 규칙이고, 냄새 입력은 벽 여부로 정해진다.
5. **KC 상위 $k$ 동률 난수**: `make_rng(실행 시드, 판 번호, "kc_tiebreak")`을 (시험, 변형)마다 새로 만들어 표본 순서대로 쓴다. 배정 시드와 무관하다.
6. **시험별 제외** (동률 허용오차는 로그 변환 뒤 $10^{-6}$):

| 시험 | 제외 |
|---|---|
| 1 | $\|L\| < 2$, 합법 방향 냄새가 모두 0, 최적 방향이 유일하지 않음 |
| 2 | $\|L\| < 2$ |
| 3 | 페로몬 입력이 없거나 동률, 짝이 없음 |
| 4 | 13.3의 기본 표본 조건 미충족 |

   제외 비율은 시험마다 보고한다.
7. **시험 3 페로몬 짝**: 같은 분할에서 **같은 $(L, \text{벽 마스크})$이면서 다른 판**(실행 시드 또는 판 번호가 다른 것)의 표본에서만 고른다. 없으면 그 표본은 제외하고 제외율에 센다. 이유: 같은 판의 인접 틱이 뽑히면 페로몬이 원래 냄새와 거의 같아진다. 고르는 난수는 `make_rng(실행 시드, 판 번호, "repr_synth")`.
8. **시험 2 예측**: 합법 마스크 없이 이진 `predict`. 균형 정확도는 $z \in \{0, 1\}$에 대해 계산한다.
9. **표본 수 확인 (13.5)**: 분할마다 한 번, 측정 전에 개발-학습과 개발-평가만 한다. 미달이면 "자료 부족"으로 기록하고 멈춘다. 최종 검증 분할은 단계 4에서 확인한다.
10. **분류기와 실패 이유**: 개발-학습 유일 표본으로 학습, 개발-평가로 판정. 실패 이유는 "정확도 미달", "분류기 비수렴"(`ConvergenceWarning`을 잡음), "자료 부족" 중 하나.
11. **보조 ② 누적 $\mathbf h$ (후보 하나에 대해서만, 판정에 안 씀)**: $\mathbf h \leftarrow (1-\kappa)\mathbf h + \mathbf k$를 초파리별 전체 틱 이력에 재현하고 확정 · 먹힘 · 목숨 끝에서 비운다. 합성 $z$는 직전 초기화 이후 구간 전체에서 바꾼다. **시험 1, 2, 4에 한다. 시험 3은 건너뛴다** (구간에 걸친 페로몬 합성 방식을 4절이 정하지 않았다). 시험 4의 냄새 맞바꿈도 $z$와 같은 방식으로 **직전 초기화 이후 구간 전체에서** 두 채널 값을 맞바꾼다. 결정 틱에만 바꾸면 $\mathbf h$의 대부분이 맞바꾸지 않은 이력이라 원본과 교환 변형의 $\mathbf h$가 거의 같아지고 정답만 반대가 되어 "누적하면 정보가 사라진다"는 틀린 결론이 나온다. 단 구간 중 초파리가 방향을 틀면 자기중심 채널의 뜻이 바뀌므로 이것은 **"그 구간 동안 두 감각 채널이 뒤바뀐 경우"의 근사**다. 보고에 적는다.
12. **가짜 엔진의 한계**: 가짜 엔진은 파워 쿠키가 없어 $z$가 항상 0이다. 그래서 $z = 1$은 시험 2 · 4의 합성 변형에만 있고, "실제 관측(통제 없음)의 과제 C 정확도"(13.3)는 $z = 0$ 표본만으로 계산할 수 있다. 그 사실을 보고에 적는다.
13. **보조 ①은 주 판정과 같다**: 모든 배정 시드에서 KC 1,575개 모두가 MBON에 연결되어 있다 (확인함). "MBON에 연결된 KC"와 "모든 KC"가 같으므로 보조 ① 결과는 주 판정과 같다고 기록하고 다시 계산하지 않는다.
14. **이번 단계 범위**: 개발 자료(실행 시드 1000 ~ 1019)만 만들고 180개 조합을 모두 측정한 뒤 멈춘다. 최종 검증(지시서 5절)은 하지 않고, 최종 검증 자료(2000 ~ 2009)는 만들지 않는다. `configs/brain_v1.yaml`의 시드 · $\rho$ · $\theta$는 관리자 승인 뒤에 바꾼다 (커밋 메시지에 "단계 3 선정 결과 반영").


## 14. PPO 팩맨 학습 (PR #9, 관리자 인수 2026-11-08)

### 14.1 보상의 시점 (결정 9)

- **시간 항(`time_step`)과 근접 항(`ghost_proximity`)은 팩맨이 실제로 움직인 틱에만 준다.** "움직였다" = 팩맨의 칸이 이번 틱에 바뀌었다(틱 시작 `begin`의 `pac_cell` ≠ 틱 끝 `pac_cell`). 속도 누적기(TRD 7.2) 때문에 팩맨은 매 틱 움직이지 않는다. 서 있는 틱에도 벌점을 주면 학습 신호가 속도 설정(0.8 · 0.9)에 따라 달라지고, 원 저장소(한 스텝 = 한 칸 이동)와도 어긋난다. 사건 항(먹기 · 사망 · 클리어)은 움직임과 무관하게 준다.
- **목숨을 잃은 틱의 근접 항은 원 저장소(`third_party/pacman_ai/engine/game.py` `step_game` · `compute_reward`)대로 계산한다.** 원 저장소는 사망 처리에서 위치를 처음으로 되돌린 뒤(`reset_positions`) 그 상태로 `compute_reward`를 부르고, 목숨이 다 떨어져 판이 끝나면 되돌리지 않으므로 잡힌 순간의 배치로 계산한다. 같은 규칙을 따른다: 목숨이 남으면 초기화 뒤 배치(다음 `begin`의 views), 판이 끝나면 잡힌 순간의 배치(`TickOut.now`). 사망 틱은 팩맨이 움직이지 않았어도(유령이 걸어와 잡은 틱) 근접 항을 계산하고, 시간 항은 이동 여부를 따른다.
- 이유: 원 저장소와 같은 보상 신호를 유지하면서(사망 근접 항) 엔진의 틱 단위가 원 저장소의 스텝 단위와 다른 것(서 있는 틱)만 바로잡는다.
- 구현: `pacman/rewards.py` 모듈 docstring, 고정 사례 시험 `tests/test_pacman_obs.py::test_rewards_fixed_cases`(이동 / 정지 / 사망 / 판 종료 / 클리어 / 중단).
- 먹힘 순번은 엔진 상태에서 얻는다 (14.3절). 클리어 · 중단 틱의 근접 항은 틱 끝 배치(`now`)로 계산한다.

### 14.2 반전 (결정 10)

- **탐욕 행동은 반전 금지 마스크를 쓴다** (`obs.mask_reverse: true`, 원 저장소의 학습용 행동 마스크: 다른 길이 있을 때만 반전을 막는다). 학습 중 표본 추출도 같은 마스크다. 학습과 실험이 같은 정책 모양을 갖는다.
- **ε 무작위 행동은 엔진의 합법 방향 전체(반전 포함)에서 균등하게 고른다** (TRD 12.2: "그 틱에 가능한 방향 중 균등"). 반전 금지는 엔진 규칙이 아니라 학습용 마스크이므로, 난이도용 무작위 행동까지 막으면 TRD의 "가능한 방향"보다 좁아진다. 팩맨 반전 허용은 TRD 7.3의 규칙이다.
- 이유: 탐욕 정책은 학습한 대로(반전 금지 마스크 안에서) 두고, ε만 엔진이 허용하는 행동 전체로 흔들어 "약한 팩맨"이 반전도 하게 한다.
- 구현: `PacmanObserver.legal`(탐욕) / `PacmanObserver.engine_legal`(ε), `PPOPacman.act`. 시험 `tests/test_pacman_trainer.py::test_ppo_pacman_controller`.

### 14.3 그 밖의 계약 (관리자 승인)

- **초 → 틱 변환은 `core/timing.py`의 `seconds_to_ticks` 하나만 쓴다:** `round(초 × time.v_max_tiles_per_s)` (파이썬 `round`). 파워 시간은 설정 `engine.power_s`(초, 참고값 6)이고, 관측의 파워 분모가 이 함수로 틱이 된다(약 57). 진짜 엔진도 같은 함수를 쓴다(`engine/game.py` docstring). Codex 엔진 브랜치(`pacman/taeyoung-engine`)에는 파워 시간 키가 아직 없어 `engine.power_s`로 정했다 — **Codex에 알릴 것.**
- **`GameView.ghost_streak` 계약:** 파워 시작 때 0, 초파리를 먹을 때마다 1 증가, 파워가 끝나도 지우지 않는다. 그 틱의 k번째 EATEN의 순번 = `ghost_streak − (EATEN 수) + k`, 따라서 매 틱 `ghost_streak − EATEN 수 ≥ 0`. 학습 환경은 위반하면 멈춘다. `Event`에는 필드를 더하지 않는다(4절 유지).
- **엔진 숫자(파워 분모 · 초기 목숨)는 엔진 설정에서만 가져온다**(`pacman/obs.py::engine_constants`). 체크포인트에 `engine_constants`로 기록하고, 실험 시작 때(`PPOPacman`) 실험 설정의 값과 다르면 멈춘다. `Trainer.load`도 대조한다.
- **조건 이름은 추론하지 않는다.** 커리큘럼 단계마다 `condition`을 설정에 적고(`random`→`regime1`, `original`→`b1`), 평가 상대도 `training.eval_opponent: {ghosts, condition}`에 적는다. `uses_views`와 `condition == "b1"`이 맞아야 하며 시작할 때 검사한다.
- **난수:** 학습 환경의 엔진 · 유령은 실행기와 같은 용도 이름("engine", "ghost")의 칸별 `GameRngs`이고, `OriginalGhosts`와 `PPOPacman`도 `GameRngs`를 받아 판마다 `TickCore`가 다시 만든다(11절). `OriginalGhosts` 자리 파일의 생성자 셋째 인자가 `rng`에서 `rngs: GameRngs`로 바뀌었다.
- **설정은 둘:** `configs/pacman_train_smoke.yaml`(연기 시험용: 가짜 엔진 · 무작위 유령 · 평가도 무작위 유령)과 `configs/pacman_train_v1.yaml`(본 학습용: 진짜 엔진 · 무작위 → 원작 유령, 평가는 원작 유령). 학습은 시작할 때 모든 부품(엔진 숫자, 엔진, 단계별 유령, 평가 상대)을 만들어 보고 모자라면 시작하지 않는다(종료 코드 3). 본 학습용은 진짜 엔진 · B1이 병합되기 전에는 이 검사에서 멈추는 것이 정상이다.
- **학습 일정과 멈출 지점:** 총 길이(`training.total_updates`)는 체크포인트와 설정 해시에 들어가고(바꾸면 재개할 수 없다), 학습률 · 엔트로피 일정은 언제나 이 값으로 계산한다. 이번 실행을 멈출 지점은 별도 인자(`--stop-at`, `Trainer.train(stop_at=...)`)이며 일정에 영향이 없다. 학습 종료는 평가 승률이 평탄해지는 시점으로 판단한다.
- **평가에서 CENSORED 판**은 승률 분모 · 평균 점수 · `best.pt` 선택에서 빼고 `eval_log.csv`의 `censored` 열에 따로 센다(`unfinished`는 제한 틱 안에 끝나지 않은 판). 계산할 판이 없으면 최고로 뽑지 않는다.
- **체크포인트 저장 형식 번호 2:** 불러올 때 번호 · 관측 규격 버전이 다르면 멈추고, 저장한 커밋이 지금 코드와 다르면 경고만 낸다.
