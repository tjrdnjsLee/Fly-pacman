# 2. 주제별 해설

## A. 반전 기록

### A1. "상태 전환 시 반전 횟수"를 센다

- **무엇.** `flies.csv`의 "반전 횟수"는 빈칸 (TODO) → 결정을 요청받은 틱에서 BACK이 합법인 기회 중 확정된(`committed`) 행동이 BACK인 횟수. 지연 반전은 저장한 틱에 센다.
- **왜.** PRD 10.4의 학습 증거 "상태 전환 순간 반전을 고르는 비율"을 계산할 열이 비어 있었다.
- **왜 반드시.** 기회만 있고 횟수가 없으면 비율을 낼 수 없다. 지연 반전을 저장 틱과 적용 틱에 두 번 세면 횟수가 기회보다 커질 수 있다 (횟수 ≤ 기회가 항상 성립해야 한다).
- **의미.** 뇌가 아닌 조종기도 같은 정의를 쓴다. B1은 반전을 강제하며 결정을 요청받지 않으므로 0이다 (실행으로 확인). 이 값은 파워 전환의 기회만이 아니라 BACK이 합법인 모든 결정 틱을 포함한다.
- **출처.** D§23, PR #43.

### A2. 원인별 네 열

- **무엇.** `flies.csv` 끝에 파워 시작 반전 기회 · 횟수, 파워 종료 반전 기회 · 횟수. 기존 합계 두 열은 그대로다.
- **왜.** 파워 시작과 종료에서 배운 초파리의 반전 방향이 반대일 수 있다.
- **왜 반드시.** 합친 비율은 학습이 되어도 두 방향이 상쇄되어 평평하게 나올 수 있다. 그러면 "반전을 배우지 않았다"로 잘못 읽힌다.
- **의미.** 합계에서 두 원인을 뺀 값이 원인이 없는 기회(막다른 길 등)다. 통합 실행(regime1, 40판)에서는 0이었다.
- **출처.** D§23, PR #43.

### A3. 체제 2 · 3의 분배 몫은 `1/F`, `q/F`

- **무엇.** 코드의 `0.25`, `q/4` → `1/F`, `q/F` (값 같음, $F = 4$). 체제 2는 D§23에서, 체제 3은 D§29.5에서 맞췄다.
- **왜.** 점검 지적 9: 체제 3이 숫자를 직접 적고 있었다.
- **의미.** 체제 2와 3의 차이는 페로몬뿐이다 (H).
- **출처.** D§23, D§29.5, PR #43, PR #52.

## B. 팩맨 난이도 $\varepsilon$ (TRD 미결 7, PRD 미결 6)

### B1. $\varepsilon$을 B0의 성능으로, 측정 전에 정한 규칙으로 고른다

- **무엇.** 후보 $\{0, 0.1, 0.2\}$ 중 $0.10 \le W_{\text{B0}} \le 0.50$이고 판당 활성 후 포획 $\ge 1$인 가장 작은 값. 후보가 없을 때의 처리도 미리 정했다.
- **왜.** 모든 체제는 $w = w^{(0)}$에서 시작하므로 학습곡선의 출발점은 B0의 성능이다.
- **왜 반드시.** 출발점이 바닥이나 천장에 붙으면 학습 효과를 잴 수 없다. 체제 조건의 결과로 고르면 원하는 체제가 이기는 난이도를 고를 수 있다. 그래서 B0만 보고, 측정 전에 규칙을 적었다.
- **의미.** 가장 작은 값을 고르는 이유: 학습한 팩맨에 가장 가깝고 무작위 행동의 잡음이 가장 적다. 0.10과 0.50은 판단으로 정한 값이다. 시드 7000 ~ 7009는 본 실험에 쓰지 않는다.
- **출처.** D§24.1 ~ D§24.5, PR #44.

### B2. 결과: $\varepsilon = 0$

- **무엇.** B0의 $W$는 $\varepsilon = 0$에서 0.351, 0.1에서 0.846, 0.2에서 0.968. 조건을 모두 만족한 후보는 0.0뿐이다. 중단 비율은 모두 0.
- **의미.** $\varepsilon = 0$에서 B0(0.351)가 B1(0.030)보다 크고, 0.1에서는 순서가 뒤집힌다. 팩맨은 원작 유령 상대로만 학습했다 (PRD 8의 해석 주의).
- **출처.** D§24.6, PR #45.

## C. 실험 회로 파일 (TRD 미결 24)

- **무엇.** 뇌가 원본 + 배정 설정 + 시드로 회로를 다시 조립 → `configs/brain_v1.yaml`의 `circuit.file`(`mb_v1.npz`)을 읽고, 그 전에 meta 일곱 항목(파일 해시, 원본 해시, 배정 설정 해시, 배정 시드, $\rho$, $\theta$, 하이퍼파라미터 해시)을 대조한다. 회로 해시는 원본의 sha256 → **`mb_v1.npz`의 sha256**. 뇌 저장 형식 2 → 3.
- **왜.** TRD v0.6이 "본 실험 전에 바꾼다 **[권장]**"으로 남겨 둔 일이다.

- **확인.** 순서 효과 측정(D)의 회귀 대조에서 B0의 CSV 셋이 ε 측정과 바이트 단위로 같았다. 회로 파일 전환은 행동을 바꾸지 않았다.

## E. 가중치 저장, 재개, 최종 평가 (TRD 미결 10 · 11 · 23)

### E1. `weights/*.npz`

- **무엇.** TRD v0.6 "판 경계마다 $w$, $\bar R$, 난수 상태, 진행 번호, 아직 구현되지 않음" → 학습 조건의 칸마다 **100판마다와 마지막 판에**, 연결 마스크 안의 $dw$ (float64), $\bar R$, 시드, 판 번호, 조건, 회로 해시, 뇌 설정 해시, 실행 설정 해시. 칸 · 판 하나에 약 0.6 MB.
- **왜 반드시.** 최종 평가는 학습한 가중치를 고정해 따로 돈다 (TRD 13.5). 가중치가 남지 않으면 평가할 수 없다. 해시 셋이 있어야 다른 회로 · 다른 설정의 가중치를 잘못 불러오는 것을 멈출 수 있다.
- **의미.** 저장을 켜도 CSV와 재생 로그는 바이트 단위로 같다.
- **출처.** D§26.1, PR #48.

### E2. 재개 명령은 만들지 않는다

- **무엇.** TRD 13.6의 재개 **[권장]** → 만들지 않는다. 중단되면 그 조건을 같은 시드로 처음부터 다시 돈다.
- **왜.** 조건 하나가 몇 시간 안에 끝나고, 같은 장치에서 결과가 결정론적이다.
- **왜 반드시.** 재개는 시작 판 번호 · 난수 복원 · 묶음 구성이라는 새 코드 경로를 만든다. 그 경로가 끊지 않은 실행과 같은지 따로 보증해야 한다. 쓰지 않을 경로의 보증 비용을 지지 않는다.
- **의미.** D§12.5의 재개 설계는 기록으로 남는다. 체크포인트 대조(회로 · 설정 해시)는 최종 평가의 불러오기에 그대로 쓴다.
- **출처.** D§26.2, PR #48.

### E3. 평가 정책: 학습 때와 같은 표본 추출 (TRD 미결 10)

- **무엇.** TRD 13.5 "최댓값 선택 또는 고정 $\beta$ 표본 **[미결]**" → $\pi_a \propto e^{\beta x_a}$, $\beta$ 그대로, $\eta = 0$.
- **왜 반드시.** (1) REINFORCE형 학습이 다듬는 것은 확률 정책이다. (2) B0는 표본 추출 정책으로 정의되어 있고 $\varepsilon$도 그 B0로 골랐다. 최댓값 선택은 B0를 다른 정책으로 바꿔 기준선과 어긋난다. (3) $\varepsilon = 0$의 팩맨은 결정론적이라, 초파리까지 결정론적이면 순환으로 중단 판이 생길 수 있다.
- **출처.** D§26.3, PR #48.

### E4. 평가 절차

- **무엇.** 학습 시드 8000 ~ 8009와 평가 시드 9000 ~ 9009를 **위치로 짝짓는다.** 칸마다 200판. 시드별 평균 $Y_s$ → 짝 차이 $\Delta_s$의 평균과 95% 신뢰구간($t$, 자유도 9). 10쌍 모두 보고. 대표 지표는 팩맨 평균 점수, 보조 지표는 $W$. 다중 비교 보정은 하지 않고 그 사실을 적는다.
- **왜 반드시.** 독립 반복 단위는 학습 시드다 (PRD 10.6). 판을 독립 표본으로 다루면 신뢰구간이 거짓으로 좁아진다. 결과를 보기 전에 판단 기준("체제와 B0의 짝 차이 신뢰구간이 0을 포함하지 않는다")을 적어 두어야 결과에 맞춘 기준을 고를 수 없다.
- **의미.** 0.95와 200판은 판단으로 정한 값이다. 두 시드 범위는 다른 곳에 쓰지 않는다 (G6).
- **출처.** D§26.4, PR #48.

## F. 동시 실행 결정론과 본 실험 규모 (TRD 미결 9 · 14, PRD 미결 9)

### F1. 측정은 학습 결과를 보지 않는다

- **무엇.** 다섯 조건을 배치 S(차례로) · A(조건당 프로세스 하나, 동시) · B(조건당 둘, 동시)로 30판씩 돌려 해시 · 게임-틱 합 · 시간만 남긴다. 승패 · 점수 · 보상은 출력하지 않는다.
- **왜 반드시.** 이 측정은 체제 조건을 돌린다. 규모를 학습 결과로 정하면 결과에 맞춘 규모를 고르게 된다.
- **출처.** D§27.1 ~ D§27.3, PR #49.

### F2. 결과: 배치 A, 시드 10, 3000판

- **무엇.** S–A는 다섯 조건 모두 같았다 (동시 실행 결정론 확인). A–B는 학습 조건의 **가중치 파일만** 달랐다 (CSV 셋은 같음). 그래서 A. $T$ = 98.3초, $\hat T(3000)$ = 4.277시간 $\le$ 8시간 → **3000판, 밤 하나.**
- **왜 A–B가 달랐나.** 뇌의 MBON 구동을 묶음 전체에 한 번에 계산하므로, 묶음 크기가 바뀌면 덧셈 순서가 바뀌어 부동소수점 마지막 자리가 달라진다. B0는 $dw = 0$이라 같다. 칸끼리의 결합이 아니다.
- **왜 반드시.** 비트 단위로 재현하려면 같은 배치(조건당 프로세스 하나, 시드 10개 한 묶음)로 돌아야 한다. 그래서 분할 수를 설정에 두고 대조한다 (G5).
- **의미.** 규칙 $\hat T(n) = T \times (1.5\,n + 200)/30 \le 8$시간의 8시간과 1.5는 판단으로 정한 값이다. 동시 실행으로 S 대비 2.7배 빨라졌다.
- **출처.** D§27.4, D§27.5, PR #49, PR #50.

## H. 체제 3 페로몬 방출 규칙 (PRD 미결 1, TRD 미결 5)

### H1. 종류: 추격(중계) 하나

- **무엇.** PRD 7.4 "방출 조건과 종류(추격용, 경고용 등) **[미결]**" → 팩맨 냄새를 동료에게 중계하는 한 종류.
- **왜.** 페로몬이 냄새가 못 하는 일은 멀리 있는 동료에게 정보를 전하는 것이다 (PRD 7.4의 참고).
- **왜 경고용은 없나.** 겁먹음은 파워 쿠키로 방출된 초파리 모두에게 동시에 걸리고, 각자 자기 $z$로 이미 안다. 전할 정보가 없다.
- **출처.** D§29.1, PR #52.

### H2. 방출식: 농도 비례, $\kappa = 0.5922$

$$
E_k = \kappa\,\hat c_k\,\mathbb 1[z_k = 0],
\qquad
\hat c_k = c_0\big(e^{\max_a o_{k,a}} - 1\big),
\qquad
\kappa = \frac{1}{\bar c}
$$

- **무엇.** $\hat c_k$는 로그 관측을 풀어 얻은 **네 이웃 칸 중 가장 진한 팩맨 냄새 농도**다. $\bar c = 1.6885$는 세기 1인 정지 원천이 자기 칸에 만드는 정상 상태 농도의 미로 평균, $\kappa = 0.5922$.
- **왜 농도 비례인가.** 로그 관측에 비례시키면 먼 초파리도 상당히 내뿜어(12칸에서 팩맨 옆의 약 35%) 중계가 흐려진다. 농도에 비례시키면 거리에 따라 냄새처럼 줄어든다 (팩맨 옆 대비 3칸 0.39, 6칸 0.16, 12칸 0.03).
- **$\kappa$의 뜻.** 팩맨 바로 옆의 초파리는 팩맨과 같은 세기 $s$를 내뿜는다. $\hat c \propto s$이므로 $\kappa$는 $s$와 무관하다.
- **왜 되먹임이 없어야 하나.** 방출은 냄새와 $z$만 보고 페로몬 관측을 쓰지 않는다. 그래서 방출 → 페로몬 → 방출의 고리가 없다. 난수도 쓰지 않는다.
- **의미.** 냄새 파라미터가 바뀌면 $\kappa$를 다시 계산해야 하고, 시험이 검사한다. 관측의 $c_0$는 냄새와 같은 0.01이다 (점검 지적 16). 그때 방출원 하나의 정상 상태 관측(거리 0 ~ 12칸에서 4.25 ~ 2.28)은 냄새(5.13 ~ 1.80)와 같은 범위다.
- **출처.** D§29.2, D§29.3, PR #52.

### H3. $D_{\text{ph}} = 4$, $\lambda_{\text{ph}} = 0.05$

- **무엇.** 자리표시 `{D: 1.0, lam: 0.1}` → $D_{\text{ph}} = 4$, $\lambda_{\text{ph}} = 0.05$. 닿는 거리 $\ell_{\text{ph}} = 8.9$칸, 냄새($\ell = 4.5$칸)의 두 배. 미로의 평균 거리는 21.1칸이다.
- **왜.** 자리표시 $\lambda_{\text{ph}} = 0.1$은 냄새보다 짧게 닿았다 (v0.6 해설서 3절).
- **왜 $\lambda$가 아니라 $D$를 바꿨나.** $\lambda$를 줄이면 정보의 수명 $1/\lambda$도 같이 늘어 오래된 위치를 전한다 ($\ell$ 두 배면 수명 네 배). $D$를 늘리면 수명은 냄새와 같은 20틱으로 두고 더 멀리 퍼진다. 대가로 같은 거리의 방향 대비는 줄어든다 (거리 9칸에서 냄새 0.50, 페로몬 0.29).
- **출처.** D§29.3, PR #52.

### H4. 해석 주의와 적용 범위

- 페로몬에는 동료를 거쳐 중계된 팩맨 쪽 정보와 동료 자신의 위치 정보가 함께 담긴다. 성능이 오르면 협동 전략 때문인지 정보량이 늘어서인지 구분해 해석한다 (PRD 7.4).
- 판단으로 정한 것: 추격 한 종류, $\ell_{\text{ph}} = 2\ell$, "팩맨 옆에서 팩맨과 같은 세기", 농도 비례.
- `main_v1`, `m3_curve_v1`, `final_eval_v1`의 `phero` = `{D: 4.0, lam: 0.05, gain: 0.5922}`. 닫힌 실험의 설정은 그 실행의 자리표시로 남는다.
- 결과를 아무도 보지 않은 상태에서 정했다 (규모 측정의 눈가림, M3 곡선 전).
- **출처.** D§29.4, D§29.5, PR #52.

### I1. M3 곡선: 미리 정한 확인 항목 모두 통과

## K. 문서 정리의 보충

### K1. "최강 방향 회피"는 상태별로 나눠 보고한다

- **무엇.** 계산 정의(D§17.6: 합법 방향 중 냄새가 가장 센 방향 집합 밖을 고른 비율, 우연 기준은 표본별)는 그대로 두고, 보고를 $z$로 나눈다. 겁먹은 상태($z = 1$)의 값이 PRD 10.4의 지표이고, 평소 상태($z = 0$)의 값을 나란히 보고한다.
- **왜.** PRD 10.4는 "겁먹은 상태의 결정"으로 한정했고, D§17.6은 모든 결정 시점으로 정의해 두 문서가 달랐다 (PR #53 검토).
- **왜 반드시.** 가장 센 냄새 쪽은 평소에는 팩맨에게 다가가는 쪽이고, 겁먹었을 때는 위험한 쪽이다. 같은 비율이 두 상태에서 반대의 뜻을 가지므로 합치면 해석할 수 없다.
- **의미.** 계산은 재생 로그에서 한다 (D§28.5). 이 지표는 아직 아무도 계산하지 않았으므로 결과를 보고 정한 규칙이 아니다.
- **출처.** D§31.1, PR #53.

### K2. 코드에 이미 있는 사실은 코드를 출처로 적는다

- **무엇.** 인터페이스 이름(`FlyBrain.slot_state`, `load_slot_state`, 설정 키 `evaluate`, `WEIGHTS_FORMAT = 1`)과 난수 용도 번호 0 ~ 9(`core/rng.py`의 `PURPOSES`)를 TRD 5.5 · 13.2에 적고, 출처로 코드 파일과 줄을 단다.
- **왜.** 이 판의 규칙("옮기는 내용은 DECISIONS에 있어야 한다")으로는 DECISIONS에 이름이 없는 구현의 사실을 TRD에 적을 수 없었다.
- **왜 반드시.** 결정이 아닌 것을 결정으로 꾸며 DECISIONS에 넣으면 결정 기록이 흐려진다. 반대로 TRD에서 빼면 인터페이스 문서에 실제 이름이 빠진다. 출처를 코드로 두면 둘 다 피한다.
- **의미.** 바꾸려면 코드와 TRD를 함께 바꾼다.
- **출처.** D§31.2, PR #53.

# 5. 결정 기록을 다루는 규칙

v0.6 해설서 5절의 원칙("결과 전에 고정한다", "출처는 하나" 등)을 그대로 따른다. 이 판에서 더한 것:

1. **DECISIONS의 옛 절은 지우거나 고쳐 쓰지 않는다.** 결정 기록이기 때문이다. 나중 절이 바꾼 곳에는 그 항목 끝에 `(→ D§n에서 바뀜)`만 더한다.
2. **PRD · TRD에 옮기는 모든 내용은 DECISIONS에 이미 있어야 한다.** 옮긴 곳마다 `(D§n)`으로 출처를 단다. 문서 정리가 새 결정을 만드는 통로가 되지 않게 한다.
3. **닫힌 실험의 재현은 그 실험의 커밋에서 한다** (D§30.4). 지금 main의 문서와 코드는 지금 실험의 기준이다.
